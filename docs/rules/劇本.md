# 劇本

- 16:9、24fps，每支獨立成篇。（頻道規格；24fps 也是將來訓 LoRA 的前提）
- 開寫前先問齊人物、場景、走向、風格、禁則。（最大的浪費是批次生成完才發現共通缺陷）
- 先給 2–3 個敘事方向再寫。（一次驗收合格的片都是這樣開始）
- 製作順序：訪談 → 布置圖 → 最難的一鏡先測 → 再批次。（先整片批次才發現共通缺陷，曾 13 鏡累積 25 版）
- 寫看得見的行動，不用解說對白代替戲；反轉要能從前文線索回看成立。
- 技術限制就是寫作限制：避開快打、追逐，一鏡預設一人說話。（H3 多人對話容易配錯嘴、快動作會崩；真要同鏡對話用 `audio.voice_refs`，要聽寫比對）
- 喜劇用「神話層 × 真相層」，靠切鏡製造反差。（只靠旁白解釋笑點的版本被退件）
- 總結句用簡單常用字。（TTS 比較不會念錯）
- 劇本寫「在桌面上畫」「用手指比劃」這類不留痕跡的示意動作，改成拿筆在紙上畫。（觀眾會覺得怪）
- 台詞或旁白在數數（「一、二、三」）時，畫面不擺可以數的東西（石子、手指）；改成寫字、書寫面看不清，正確數字交給後製。（生成的數量會跟念的對不上）
- 頻道、角色專屬的禁則寫 `output/AGENTS.md`，只屬於某類影片的寫 `kinds/<類型>/rules.md`，不寫進本資料夾。
