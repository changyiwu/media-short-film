# 自審與交付

原則：**交給人看之前，agent 自己先審完、修完**。`review.py` 五遍的做法、判斷門檻與「常退件清單」在 `<repo>/docs/04_自審清單.md`，**逐條照做**；本檔補上選鏡、對嘴、後製與交付時要另外確認的事。

## 1. 選鏡與返工（逐鏡播放完整動態）

除了 `docs/04` 的常退件清單，再看：

- [ ] 提前開口／台詞前先動嘴
- [ ] 靜默時仍張嘴
- [ ] 角色增生、重複人物
- [ ] 左右換位、座位漂移
- [ ] 帽子、頭套、眼睛等道具異常（眨眼、變形）
- [ ] 手部、道具、背景漂移
- [ ] 全臉與肩頸有整體表演，不是只有嘴在動
- [ ] **成片每秒一格看一遍**（`tools/framecheck.py`，用法見 `docs/04`〈審片工具〉）：背景突然冒人、臉或手糊掉、道具不連戲、牆上冒旗子；`clipcheck.py` 標 CHECK 的鏡（H3 自己切鏡）、`colordrift.py` 列出的鏡（顏色漂移）逐一看
- [ ] 手要連到肩膀：肩膀→袖子→前臂→手是同一隻，從人在的那一側進畫面；背對鏡頭的鏡查左右手（拇指方向）
- [ ] 轉身不換臉：比首尾兩格是不是同一人
- [ ] 同場髮型、帽子、手上道具逐鏡比對（首幀並排看一次）
- [ ] 同一鏡沒有兩個聲音（疊音、回音、第二個人跟著念）；沒台詞的鏡背景沒有冒出來路不明的人聲
- [ ] 同一人、同構圖接連兩鏡會像跳切：後一鏡放大約 20% 或換鏡位
- [ ] 動作沒卡住：走路鏡看腳有沒有真的交替（首幀畫在跨步中間時 H3 只會定在那個姿勢晃）
- [ ] 大遠景另外每 0.5 秒、用 640 寬以上看一次遠處的空地、操場、走廊（遠處冒出的小人影在每秒一格的縮圖看不出來）；劇本標「鎖」的大遠景要鎖尾幀
- [ ] 握直立的桿子看大拇指：自然握法像舉火把，手背和指節朝外、四指往胸口繞、拇指壓在上面；手背靠身體、手指往外包＝左右手畫反。錯在首幀就擋下，首幀提示詞寫明哪隻手、手背與拇指朝哪
- [ ] 爬梯子的人胸口朝梯子：背面鏡的首幀提示詞拿掉胸前配件（識別證、玉佩），寫「從背後看不到臉、鞋底朝鏡頭」，否則生圖會把人轉成面朝鏡頭
- [ ] 重要角色的臉小於 25 px 修不了（精修只是 AI 自己編五官）：大遠景只留約 1.6 秒交代場面，接同場臉清楚的近景或群像；人多的場面寫劇本時就排「大遠景＋群像＋近景」
- [ ] 台詞、旁白講到的數字、日期、人數，跟同一段畫面上的數字一致

（以上幾條改寫自上游 2026-11-02～11-12 的自審清單。）

發現問題**先標原因**，只重做必要的鏡頭；**禁用嘴／眼 XY 平移貼片修法**，也不靠剪掉或插別的鏡頭躲。

## 2. 對嘴界線

- [ ] 配音與畫面用同一份音訊
- [ ] 長靜默段嘴巴閉著，身體沒有被鎖死
- [ ] 沒做逐音素量測就照實寫，不寫成「完美對嘴」
- [ ] 聽寫只差一個字也逐字判斷：同音字放過，破音字念錯就重抽；畫外旁白也要聽寫比對；有懷疑的字列在交片訊息裡。破音字先跑 `tools/poly_check.py`
- [ ] 聽寫跟原文不同的破音字，不能只量音高（F0）就判定念對：音高只看聲調、看不出聲母與整個音節，一律換同音字重抽，或只錯一兩個字時用 `tools/vc_swap.py` 換字（上游 2026-11-12，「長官」的「長」）
- [ ] 換了某一鏡的版本後，字幕時間跟實際開口時間重新比對（差 > 0.6 秒就修）

## 3. 後製

- [ ] 保比例放大，沒有拉伸畫面比例
- [ ] 字幕不是在低解析度先燒再放大
- [ ] 全片解碼正常、幀數與 24fps 正確、沒有近黑幀與削波、字幕時序對
- [ ] 有片尾時：片尾的生圖工具名稱符合實際用的後端
- [ ] 原聲關掉的鏡不是數位全靜（墊同場底噪）；沒台詞的笑聲、掌聲鏡不比台詞大聲
- [ ] 配樂沒在兩句之間彈回來（空檔不到 1 秒時壓住別放開）；換畫面時音樂不硬切，結尾自然淡出

## 4. 交付與歸檔

- [ ] 給使用者：成片路徑、自審報告（用**成片時間碼**對應鏡頭）、已知限制與沒量的項目
- [ ] 沒有片尾時：發布資訊裡要有 AI 生成標示與工具名單（MiniMax H3、Music 3 授權要求公開內容標示機器生成；生圖工具照 `work/image_backends.json`）
- [ ] **定案**：交完自審報告，最後問使用者「可以成片嗎？」，**使用者說可以才做**下面三件（還在改就不做，檔名維持 `film_1080p.mp4`，`review`、重剪都照舊找得到）：
  1. 移到片子資料夾最上層並改檔名：`work/cut/film_1080p.mp4` → `<片名>.mp4`、`work/cut/film_720p_phone.mp4` → `<片名>_手機版.mp4`（找成品只要打開片子資料夾，不用進 `work/cut/`）（片名用 `film.json`／`recast.json` 的 `title`；有接片尾的換角片是 `film_1080p_ending.mp4` → `<片名>.mp4`）。`<片名>.mp4` 已經存在（之前定案過）就先把舊的改名 `<片名>_v<N>.mp4`，不覆蓋
  2. 生成 `output/<類型>/<片名>/發布資訊.md`：照 `<repo>/templates/發布資訊範本.md` 填（AI 生成標示、工具名單照 `work/image_backends.json`）；已經有就照這版內容更新
  3. 做封面：照 `docs/02` §12〈封面〉（`cover` 技能路線 A、`work/post/vsr/` 的乾淨畫面、YouTube 版裁 1600×900 字放左上），三張開圖檢查後寫回 `發布資訊.md`
  - 定案後又要改：重跑 `cut` 會再產生 `film_1080p.mp4`，改完再問一次、再定案一次
- [ ] **技術 QA 通過 ≠ 使用者驗收通過**，分開記錄；保存使用者回饋原文，不擅自升級成「驗收通過」
- [ ] 該片 `製作紀錄.md` 補一段：版本、採用的 seed、退件原因、耗時分類
- [ ] 退件理由整理成一條規則寫進 `output/AGENTS.md`（只屬於某類影片的寫進 `output/<類型>/AGENTS.md`；不要只寫 agent 記憶：每台電腦各一份、不會同步）
- [ ] 生成的原始檔（`work/h3/<鏡>/clip.mp4` 等）保留，方便之後重剪
- [ ] 成片、角色照、參考音都在 `output/`，不進公開 repo

## 最常見的失誤（回看用）

| 失誤 | 對策 |
|:---|:---|
| 先批次生成才發現共通缺陷 | 需求訪談＋最難鏡先測 |
| 標靜止卻寫運鏡 | `action` 與 `camera` 同步檢查 |
| 誤以為鏡數等於機位數 | 預演時做機位去重 |
| 收錯輸出（把輸入素材當成品） | 只收該工作流的 Save 節點 |
| 把技術檢查當美感驗收 | 分開記錄 |
| 舊待辦蓋過新結果 | 以最新使用者決策＋採用清單為準 |
